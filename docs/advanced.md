# Техническое руководство

## Быстрый старт

```bash
git clone https://github.com/anrhangels/linux-radmir-rp.git
cd linux-radmir-rp
bash install.sh --plan
bash install.sh
```

`install.sh` готовит системные зависимости и вызывает `scripts/install.py`. Python-модули читаемые и не упакованы в скрытый сжатый установщик. Перемещение репозитория после успешной настройки не ломает запуск: рабочая копия инструментов сохраняется отдельно.

## Параметры установки

| Параметр `install.sh` | Действие |
|---|---|
| `--plan` | Показать действия без изменений и сетевых запросов |
| `--yes` | Пропустить подтверждение плана и системных пакетов; аутентификация `sudo` сохраняется |
| `--no-system-packages` | Пропустить системный пакетный менеджер; зависимости должны быть установлены заранее |
| `--prefix DIR` | Выбрать префикс вместо стандартного или сохранённого в профиле |
| `--installer FILE` | Использовать локальный официальный EXE |
| `--installer auto` | Найти наиболее свежий EXE с `radmir`, `rdmr` или `hassle` в папках загрузок |
| `--windows-fonts DIR` | Импортировать известные файлы Segoe из вашей папки Fonts |
| `--fonts-only` | Настроить шрифты для готового лаунчера в выбранном префиксе |
| `--no-hud` | Пропустить установку и настройку HUD в этом запуске |
| `--restore MANIFEST` | Восстановить изменённые файлы из снимка установки |
| `--help` | Показать справку |

`--no-hud` не удаляет ранее настроенный HUD. Для возврата прежних файлов используйте резервную копию. Подтверждение `--yes` не выбирает игру, никнейм и сервер в официальном лаунчере.

Пример отдельного префикса без HUD:

```bash
bash install.sh --prefix "$HOME/Games/radmir-custom/prefix" --no-hud
```

Префикс должен находиться внутри домашней папки. Посторонний непустой префикс без Radmir не используется автоматически. Созданный установщиком префикс отмечается `.linux-radmir-rp-managed`, что позволяет продолжить прерванную настройку. Существующая запись Radmir в Faugus не переключается на другой префикс без явного выбора.

## Параметры запуска

| Параметр команды `radmir` | Действие |
|---|---|
| `--check` | Проверить лаунчер, Proton, UMU, Faugus и библиотеки графики |
| `--restore` | Восстановить сохранённые параметры прокси и основного экрана после прерванного сеанса; не запускать игру |
| `--no-audio-fix` | Не включать обработку музыкальных адресов на этот запуск |
| `--no-display-fix` | Не менять основной экран Xwayland на этот запуск |
| `--prefix DIR` | На этот запуск выбрать другой установленный префикс |
| `--help` | Справка |

```bash
~/.local/bin/radmir --check
~/.local/bin/radmir --no-display-fix
```

Не путайте две команды: **`radmir --restore`** возвращает состояние игрового сеанса, а **`bash install.sh --restore /путь/restore.json`** возвращает файлы из снимка установки.

## Откуда берётся официальный установщик

Лента обновлений берётся с сервера, указанного в `resources/app-update.yml` официального лаунчера. В `latest.yml` читаются текущий путь и опубликованная SHA-512. Установщик проверяет адрес загрузки, корректно кодирует пробелы в URL, скачивает EXE и сверяет сумму. Номер версии лаунчера в инструкции не фиксируется.

Для явно выбранного локального EXE проверяется сигнатура файла, но опубликованная сумма автоматически не сверяется. Официальный источник — [radmir.online](https://radmir.online/). Произвольные игровые зеркала не выбираются.

Proton и UMU закреплены в `configs/downloads.json` и проверяются SHA-256. Для закреплённого Noto проверяются размер и Git blob ID. Частичный файл `.part` не запускается.

## Библиотеки графики

Winetricks устанавливает `ucrtbase2019`, `d3dx9_43`, `d3dcompiler_43`, `d3dcompiler_47` через выбранный UMU/Proton. Проверяются `system32` и `syswow64`: наличие файла, PE-сигнатура и отсутствие признака Wine builtin в заголовке.

Перед изменениями сохраняются соответствующие DLL, `user.reg`, `system.reg`, `userdef.reg` и `winetricks.log`. Готовый набор не устанавливается заново без необходимости. Запуск использует `PROTON_USE_WOW64=0` — это часть исходного проверенного подхода.

Проверка файлов не заменяет запуск новой графики в игре. [Причины исправлений →](fixes.md)

## Сеанс, блокировки и восстановление

Одна файловая блокировка охватывает весь запуск: проверку отсутствия уже запущенного Radmir, возврат прерванного состояния, включение помощника музыки, настройку экрана, работу лаунчера и завершение.

Планы возврата прокси и экрана сохраняются перед изменениями. Для разных префиксов используются разные каталоги сеанса. При ошибке восстановления прокси его план остаётся на диске и повторно обрабатывается при следующем запуске или `radmir --restore`.

Помощник музыки слушает только `127.0.0.1` на свободном порту. Перекодируется путь только HTTP-адресов `music.radmir.online`; прочие HTTP GET-запросы передаются без такой замены, HTTPS проходит туннелем без расшифровки. Это не универсальный HTTP-прокси для произвольных методов и не системная сетевая настройка.

Выбор экрана использует реально подключённый выход 1920×1080, без фиксированных имён портов. Вызов `xrandr` меняет только признак primary; режим и геометрия не переключаются. Если пользователь сам выбрал другой основной экран, возврат не затирает его выбор. Восстановление после сбоя требует доступного Xwayland.

## Пути и XDG

| Данные | По умолчанию |
|---|---|
| Игровой префикс | `~/Games/radmir-crmp/prefix` |
| Proton, UMU, HUD, профиль и рабочие инструменты | `~/.local/share/linux-radmir-rp/` |
| Скачанные компоненты | `~/.cache/linux-radmir-rp/` |
| Журналы и снимки установки | `~/.local/state/linux-radmir-rp/` |
| Планы возврата игровых сеансов | `~/.local/state/linux-radmir-rp/sessions/` |
| Пользовательские шрифты | `~/.local/share/fonts/linux-radmir-rp/` |
| Команда запуска | `~/.local/bin/radmir` |
| Ярлык меню | `~/.local/share/applications/linux-radmir-rp.desktop` |
| Записи Faugus | `~/.var/app/io.github.Faugus.faugus-launcher/data/faugus-launcher/games.json` |

Поддерживаются XDG_DATA_HOME, XDG_STATE_HOME, XDG_CACHE_HOME и XDG_CONFIG_HOME. Для нестандартного расположения используйте абсолютные пути; цели восстановления файлов должны оставаться внутри домашней папки. Файл `profile.json` сохраняет выбранный префикс для дальнейшего запуска.

Для запуска через наш помощник используются копии инструментов и прямой вызов UMU внутри Flatpak. Запись Faugus тоже создаётся, но запуск через его интерфейс сам по себе не включает музыкальный помощник и выбор экрана. Для этих исправлений используйте `radmir` или наш ярлык.

## MangoHud

Ветка расширения определяется по runtime Faugus. Локальные библиотеки и манифесты подготавливаются для доступа из Flatpak/UMU. Ограничение FPS не задаётся.

- F10 — минимальный, подробный, скрытый режимы.
- F12 — показать или скрыть панель.
- Левый Shift + F4 — перечитать конфигурацию.

Часть датчиков может быть недоступна внутри контейнера. Для повторной настройки после обновления расширения при закрытых игре и Faugus можно повторить `bash install.sh`; существующий лаунчер и готовые библиотеки используются повторно.

## Восстановление файлов

При установке печатается путь `restore.json`. Закройте игру, лаунчер, Faugus и другие приложения, использующие восстанавливаемый префикс. Затем выполните из папки репозитория:

```bash
bash install.sh --restore "$HOME/.local/state/linux-radmir-rp/backups/ДАТА/restore.json"
```

Замените `ДАТА` реальным именем папки. Найти планы можно командой:

```bash
find "$HOME/.local/state/linux-radmir-rp/backups" -name restore.json -print
```

Если восстанавливаете нестандартный префикс, передайте также тот же `--prefix DIR`, с которым он устанавливался. При изменённом XDG_STATE_HOME используйте соответствующий путь состояния.

Снимок возвращает сохранённые версии изменённых файлов и удаляет записанные в плане новые файлы. Это **не удаление всей установки**: системные пакеты, Flatpak, игровой префикс, скачанные компоненты и дополнительные файлы, созданные сторонними установщиками, остаются. Реестр и `games.json` возвращаются целиком к состоянию снимка: учитывайте добавленные позднее игры и настройки.

Сеансовое восстановление выполняется отдельно:

```bash
~/.local/bin/radmir --restore
```

Команда относится к сохранённому или явно переданному префиксу. Если восстанавливать нечего, она не запускает игру.

## Разработка и проверки

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh
bash install.sh --plan
```

Тесты используют временные файлы и имитацию внешних запусков. Системные пакеты, игру, сетевые загрузки и реальную смену экрана они не выполняют. Автоматические проверки не заменяют полноценный игровой тест.

Для изменения иллюстраций нужен pycairo: `python3 assets/create_art.py`. Установке игры Cairo не нужен. [Оформление серии →](design-system.md)
